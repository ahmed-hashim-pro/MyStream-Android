The “More” page needs a spine

Today it is twelve equal tiles in a flat grid — Zakat Calculator carries the same visual weight as Prayer Times, nothing is grouped, and a SearchView already exists in OtherCategoryFragment but is never shown. Three directions below, all built from the app's own navy-and-gold tokens. Every frame is drawn at the real 412dp device width.

  • No hierarchyTwelve identical tiles. A daily tool and a once-a-year tool look the same.
  • Wasteful vertically132dp tiles mean ~9 of 12 items fit; the rest need a scroll.
  • Labels wrap awkwardly“البث المرئي المباشر”, “أذكار الصباح والمساء” break to two lines.
  • Search is built but hiddenThe fragment already holds a SearchView. It is never surfaced.
  • Nothing is liveA tile can't say the next prayer is in 41 minutes, or that a streak is at 12 days.
  • The athkar bubble covers a tileIt parks over the top-trailing card and hides it.

Where it stands

current build

Captured from the emulator just now, Arabic, light theme.

A · Grouped rows

recommended

Three named groups, compact 52dp rows, and a right-hand slot that can carry live state. All thirteen tools fit one screen with room to grow, and the row is the only shape here that can say الفجر · بعد ٤١ د without a redesign.

  • GainsScales past 20 items · live state per row · one screen, no scroll · longest labels stop wrapping
  • CostsLoses the icon-grid look users know · least visually rich of the three

B · Sectioned grid

lowest risk

The same grid users already know, but grouped and tightened: 92dp tiles instead of 132dp, single-line labels, and the icon sitting in a tinted chip so it reads as a target rather than a decoration. Keeps muscle memory; adds the spine.

  • GainsFamiliar · all 13 fit without scrolling · grouping arrives with no relearning
  • CostsStill can't show live state · long Arabic labels stay tight at 3 columns

C · Context first

boldest

Opens with what the user actually came for — the next prayer, drawn from the location and method work just shipped — then four pinned shortcuts and a dense 4-across grid for the rest. The page stops being a drawer and starts being a dashboard.

  • GainsAnswers before it asks · densest layout · pins let each user shape their own top row
  • CostsBiggest departure · duplicates the home screen's prayer card · pinning needs new storage + an edit mode

Shared across all three

Whichever direction wins, these come with it.

My pick is A. The page's job is finding one of thirteen-and-growing tools, and rows are the only one of these three that can carry live state — next prayer, athkar read or not, reading streak — which turns a drawer into something worth opening. B is the safe choice if you'd rather not spend users' muscle memory. C is the most striking but duplicates the home screen's prayer card and needs pin storage plus an edit mode before it can ship.
